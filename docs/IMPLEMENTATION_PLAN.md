# Implementation Plan: Retinova

## Architecture Decisions

- GitHub Pages hosts a safe static frontend; secrets and Python inference never run there.
- Public preview defaults to an explicit demo state rather than exposing the Roboflow key.
- Real Grad-CAM requires a PyTorch model controlled by this repository.
- Data splits are grouped by patient ID before any model evaluation.

- [x] Rebrand all public surfaces to Retinova.

- [x] Add public README, model status, privacy notice, and team training guide.
- [x] Add static validation tests and GitHub Pages workflow.
- [x] Deploy, smoke-test the URL, and generate a QR code.

- [ ] Run accessibility, security, responsive, and presentation QA.

## Risks and Mitigations

| Risk | Impact | Mitigation |
|---|---|---|
| Only ~20 days before the event | High | Publish a truthful preview first; prioritize model evidence over extra screens. |
| Existing Roboflow model cannot expose internal activations | High | Train a controlled PyTorch model for Grad-CAM. |
| Left/right eye leakage inflates metrics | High | Group every split by patient ID. |
| No GPU or training time | High | Begin with EfficientNet-B0/ResNet18, smaller images, early stopping, and document limits. |
| Static hosting cannot keep secrets | High | Keep live inference behind a separate backend; GitHub Pages remains static. |
| Dataset/model licensing is unclear | Medium | Do not publish images or checkpoint until licenses are documented. |
