# Implementation Plan: Retinova

## Architecture Decisions

- GitHub Pages hosts a safe static frontend; secrets and Python inference never run there.
- Public preview defaults to an explicit demo state rather than exposing the Roboflow key.
- Real Grad-CAM requires a PyTorch model controlled by this repository.
- Data splits are grouped by patient ID before any model evaluation.

## Phase 1: Public Preview

- [ ] Remove secrets and unsafe authentication claims.
- [ ] Rebrand all public surfaces to Retinova.
- [ ] Replace fabricated medical outputs with provenance-labelled demo content.
- [ ] Add public README, model status, privacy notice, and team training guide.
- [ ] Add static validation tests and GitHub Pages workflow.
- [ ] Deploy, smoke-test the URL, and generate a QR code.

### Checkpoint: Public Preview

- [ ] Tests and static checks pass.
- [ ] Repository contains no dataset or credentials.
- [ ] GitHub Pages returns HTTP 200.
- [ ] QR code decodes to the deployed URL.

## Phase 2: Data and Evaluation Foundation

- [ ] Add dataset audit command and patient-grouped split manifest generator.
- [ ] Add versioned configuration and dependency manifest.
- [ ] Add metric computation and machine-readable evaluation report.
- [ ] Document limitations, class imbalance, and ODIR provenance.

### Checkpoint: Evaluation Foundation

- [ ] No patient ID occurs in more than one split.
- [ ] Every class has reported support and per-class metrics.

## Phase 3: Trainable Model and Real Grad-CAM

- [ ] Add PyTorch dataset and training pipeline.
- [ ] Train or import a checkpoint whose architecture and license are documented.
- [ ] Add class-specific Grad-CAM and quantitative/sanity checks.
- [ ] Add inference adapter returning prediction and heatmap provenance.

### Checkpoint: Real AI

- [ ] Inference and heatmap are generated by the same checkpoint.
- [ ] Grad-CAM changes when the target class changes.
- [ ] Test images are never used during model selection.

## Phase 4: Live AI Deployment and Competition Package

- [ ] Deploy the Python inference service on a secret-capable host.
- [ ] Connect the public frontend through an allowlisted API origin.
- [ ] Add poster-ready architecture diagram, model card, demo script, and offline fallback.
- [ ] Run accessibility, security, responsive, and presentation QA.

## Risks and Mitigations

| Risk | Impact | Mitigation |
|---|---|---|
| Only ~20 days before the event | High | Publish a truthful preview first; prioritize model evidence over extra screens. |
| Existing Roboflow model cannot expose internal activations | High | Train a controlled PyTorch model for Grad-CAM. |
| Left/right eye leakage inflates metrics | High | Group every split by patient ID. |
| No GPU or training time | High | Begin with EfficientNet-B0/ResNet18, smaller images, early stopping, and document limits. |
| Static hosting cannot keep secrets | High | Keep live inference behind a separate backend; GitHub Pages remains static. |
| Dataset/model licensing is unclear | Medium | Do not publish images or checkpoint until licenses are documented. |
